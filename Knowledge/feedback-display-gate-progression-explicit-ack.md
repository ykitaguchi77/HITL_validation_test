# 練習のフィードバック(模範解答)は「見た」ことを明示 OK で確認するまで次へ進ませない
- type: pattern
- created: 2026-10-10
- tags: [user-study, practice, feedback, ui-flow, overlay, webapp]

## 概要
練習で提出後に模範解答を見せる設計でも、汎用の「確認OK → 次の画面(アンケート等)」の流れに乗せると、
フィードバックは一瞬で次のオーバーレイに覆われ、読み込み前に押せば見ないまま進めてしまう。
練習時だけ専用の OK ボタン(読み込み完了まで無効)で進行をゲートし、通常の進行ボタンはその間隠す。

## 背景・きっかけ
練習2(修正ワークフロー)で、提出後に模範解答の点線 + Dice が出るが、右上「確認OK」を押した瞬間に
模範解答が消えて Paas 負荷アンケートが画像を覆っていた。「確認OK」は practice_gt の取得完了を待たずに押せたため、
練習の目的(模範解答と自分の描画の差を見て基準を揃える)が成立していなかった。ユーザーの実試用で発覚。

## 詳細
- 進行ゲートは「フィードバックが表示済み」を条件にする: OK は GT 取得完了まで disabled。
- 進む経路を 1 本にする: OK 表示中は既存の進行ボタン(確認OK)を隠す。キーボード経路(Enter 等)も同じ関数を通るか確認する。
- フィードバック後の修正→再提出ではゲートを再設定する(再び模範解答 + OK)。
- 取得失敗時は理由を表示して OK を有効化し、練習自体が詰まらないようにする(フェイルオープン)。
- 本番(フィードバック無し)の流れは一切変えない — 練習分岐に閉じた変更にし、本番セッションが従来どおりかも回帰確認する。
- 検証は稼働中サーバを避け別ポートで再現 → スクショで「覆われる」状態を確認してから修正、修正後も同じ手順で比較。

## 適用場面
- 練習・チュートリアルで正解/模範解答を見せた後に、評価アンケートや次課題が続く被験者実験 UI 全般。
- 複数のオーバーレイ/モーダルが連鎖する画面で、ある情報を「確実に見せたい」とき。
