# チャットで URL を提示するときは直後に「)」「。」を続けない(リンク化で巻き込まれ 404 になる)
- type: lesson
- created: 2026-09-19
- tags: [communication, webapp, url, user-testing, 404]

## 概要
ユーザーに開いてほしい URL を文中に書き、直後に `)` や `。` を続けると、端末/チャット UI のリンク化が末尾の記号まで URL に含めることがある。
ユーザーは `http://localhost:8000/)。` を開いて `{"detail":"Not Found"}` を受け取り、「サーバが壊れた」に見える。

## 背景・発見経緯
ローカル起動した HITL webapp のテスト中、機能追加の報告で「ブラウザをリロードすれば反映されます(http://localhost:8000/)。」と書いた。
直後にユーザーから `{"detail":"Not Found"}` の報告。`curl` では `/`・`/js/tutorial.js` とも 200 で、uvicorn ログに
`GET /%29%E3%80%82 → 404`(= `/)。`)が 2 回並んでいたことから原因を特定。

## 詳細
- 診断手順: (1) `curl -s -o /dev/null -w "%{http_code}"` でトップと静的ファイルを叩く → (2) サーバのアクセスログで **404 のパスをデコード**する。
  `%29`=`)`、`%E3%80%82`=`。`。ログにパスが残っていれば数秒で原因が分かる。
- 対処: URL は**単独行**または**行末**に置き、括弧で囲まない・句点を続けない。末尾スラッシュも不要なら省く(`http://localhost:8000`)。
  必要なら「末尾に `)` や `。` が付かないようご注意ください」と一言添える。

## 適用場面
- ローカルサーバ・トンネル URL・OSF/GitHub のリンクなど、ユーザーにクリックしてもらう URL を含む返信全般。
- ユーザーから「Not Found」「404」の報告が来たら、まずアクセスログの**リクエストパス**を見る(サーバ側のバグを疑う前に)。
