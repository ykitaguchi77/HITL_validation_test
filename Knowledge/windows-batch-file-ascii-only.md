# Windowsバッチ(.bat)は純ASCIIで書く（日本語コメントは文字化け＆誤実行の原因）

- type: lesson
- created: 2026-06-24
- tags: [windows, batch, cmd, encoding, mojibake]

## 概要
配布用のダブルクリック起動 `.bat` に日本語コメントを入れると、cmd.exe が文字化けエラーを多発させ、ウィンドウが即閉じする。`.bat` は英語コメント・メッセージのみの**純ASCII**で書くのが安全。

## 問題と背景
- cmd.exe は `.bat` を**日本語コードページ（cp932）で解釈**する。ファイルを UTF-8 で保存して日本語コメント（`REM …`）を書くと、そのバイト列が壊れ、断片が不正なコマンドとして誤実行される（例: `'繧｢繝弱ユ繝ｼ…' は内部コマンドまたは… として認識されていません`）。
- エラーで `pause` 到達前に処理がコケるため、**「キーを押すとウィンドウが即閉じ」**に見える（実体はエラーで早期終了）。
- `chcp 65001`（UTF-8 へ切替）を冒頭に置いても、**バッチ自身のコメント行のデコードには間に合わない**ことがある（コンソール出力のコードページは変わるが、バッチのパース問題は残る）。

## 解決
- `.bat` と、そこから呼ぶ `.ps1` の**両方を英語コメント・メッセージのみの純ASCII**で書く。
- 検証は `grep -P '[^\x00-\x7F]'` が環境次第で誤判定するため、Python でバイト走査して確実に確認する:
  ```python
  for f in ('run_server.bat','run_server.ps1'):
      b = open(f,'rb').read()
      print(f, [i for i,c in enumerate(b) if c>127])  # 空リスト = 純ASCII
  ```
- 日本語の案内が必要なら、バッチ本体ではなく別の手順書（`README` / `*_guide.md`）に書く。

## 再利用方法
- 配布する起動スクリプトやランチャ `.bat` を作るときは最初から純ASCIIで書く。
- 文字化け・即閉じの報告を受けたら、まず非ASCIIバイトの有無を Python で確認する。
