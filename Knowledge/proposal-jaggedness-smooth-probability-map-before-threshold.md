# AI 提案ポリゴンの「ギザギザ」はモデル出力解像度の問題 — 事前計算側で確率マップを平滑化してから二値化し、精度不変・折れ角改善を数値で確認して成果物を差し替える
- type: lesson
- created: 2026-09-20
- tags: [hitl, user-study, proposals, postprocessing, smoothing, sam2, lora, segformer, provenance]

## 状況
被験者実験の AI 提案(眼瞼ポリゴン・虹彩/瞳孔楕円)を SegFormer(128×128 ロジット → 4 倍補間)から SAM2 decoder-LoRA(256×256 確率マップ → 512 リサイズ → 0.5 二値化)へ置き換えた。
モデル側の対 GT 指標は良好(n=128 で eyelid ASSD 2.3 px = inter-rater 相当)で、API/Playwright 検証も PASS。
ところが実ユーザー試用で「**n=128 でもピクセル単位のずれが多くてギザギザ、手直しが多い。SegFormer は滑らかだったが表示時にスムージングしていたか?**」という指摘が来た。

## 問題
- 対 GT の距離指標(ASSD/HD95)は「頂点が縁に乗っているか」しか測らず、**頂点列の微小な凹凸(折れ角)**は測っていない。凹凸は被験者の micro-move を増やし、
  時間・頂点移動回数の計測にモデル精度と無関係なノイズを乗せる(H1 時間の用量反応に混入する)。
- 表示側にスムージングは無かった。旧モデルでは**低解像度ロジットの補間が暗黙の平滑化**として働いていたため滑らかに見えていただけで、
  高解像度デコーダに替えると暗黙の平滑化が消える。設計置換時に「提案の見た目の滑らかさ」は検証項目に入っていなかった。
- 表示側(webapp)で平滑化すると、記録される `initial` と提案指標(`*_prop_assd` 等)がずれ、提案指標と最終指標の比較が壊れる。

## 解決策・手順
1. **形状指標を 1 つ決める**: jaggedness = 隣接辺の方向変化の平均絶対角(deg/頂点)。`np.arctan2` の差分を (−π, π] に折り返して平均。
2. **候補を同じ採点コードで比較**: 研究画像 20 枚 × 代表 n(高 n と中 n)で、raw / 確率マップ Gaussian σ / 輪郭移動平均 / 併用 を並べ、
   STUDY 側 `geometry`/`scoring` を import して ASSD・HD95・折れ角・点数を表にする。
   本件: σ=2 px(512 px 基準)で折れ角 12.0→9.7°、ASSD 2.42→2.43(不変)、HD95 不変。輪郭移動平均は追加効果が小さく HD95 が微増 → 不採用。
3. **採用条件**: 精度指標が不変(悪化なし)かつ折れ角が下がる、最小限の処理を 1 つだけ。目視図(raw vs 採用、拡大)も 1 枚残す。
4. **事前計算側(export スクリプト)に入れる**(表示側ではない)。`prob_to_mask()` に `cv2.GaussianBlur(p, (0,0), sigma)` → 閾値。定数名・数値・根拠(日付・数値)をコメントに書き、
   `provenance.postprocess` 文字列にも明記。**全 n・全 seed に一律**(条件間の公平性)。
5. **ハッシュ連鎖を全部更新**: 提案 JSON 再エクスポート(sha256)→ 割付 JSON 再生成(SEED 固定なので割付不変・provenance だけ変わる)→ 解析計画書・事前登録ドラフト・todo の sha256 を差し替え → API 検証 → サーバ再起動 → ユーザーにリロード依頼。
6. 平滑化前に取った試用記録は「旧提案」として区別する(解析対象外なら影響なしと明記)。

## 注意点・落とし穴
- 平滑化で消えるのは**ピクセル単位の凹凸だけ**。まつ毛など局所的に縁から外れる誤りはモデル誤差(n で減る種類)で、研究の測定対象そのものなので消してはいけない。
- σ は推論解像度基準で決め、原寸換算(本件 ≈4.7 px)も記録する。σ を大きくすると HD95 が上がり始める(σ=3 で 8.1→8.5)。
- 「表示時にスムージングしていたか?」のような**ユーザーの仮説は先に事実確認**する(していなかった → 解像度差が真因)。
- 提案の形状が変わると被験者が受け取る刺激が変わるので、本番データ収集開始後は変更しない(開始前の試用段階で決め切る)。

## 追記 (2026-09-20)
- 出典: Experimental_record/20260920.md
- 導入した平滑化を研究者(非 ML 実装者)に説明するときの組み立て: ①**パイプラインを段階で並べ、どこに入れたかを明示**(256 確率マップ → 512 拡大 → 【追加】σ=2 → 0.5 二値化 → 最大輪郭 → 等間隔頂点化 → 原寸)、
  ②σ を「モデルの 1 セル分(原寸 ≈4.7 px)」と**物理スケールで言い換える**、③「消えるもの(σ 以下の凹凸=GT に元々無いノイズ)/ 残るもの(位置の系統誤差=まつ毛の膨らみ等)」を対で言う、
  ④精度不変の数値(ASSD/HD95)と**σ の上限根拠**(σ=3 で ASSD 2.42→2.48 と劣化し始める=「ノイズは消す・形は変えない」の境目)、⑤楕円構造は `fitEllipse`(最小二乗)なので影響 ±0.1 px と構造別に影響を分ける、
  ⑥設計上の公平性(全 n・seed 一律)と「提案指標は平滑化後で再計算=被験者が見た提案の指標」を添える。
- σ の採用は「折れ角が下がる最小の σ」ではなく「**精度指標が動き始める直前の σ**」として根拠づけると、査読・共同研究者への説明が短くて済む。
