# 作業時間が主要評価の被験者実験では、教示で速度に一切触れず精度目標だけを一貫して示す(「速さは競いません」も書かない・可視タイマーは暗黙の速度教示)
- type: lesson
- created: 2026-09-20
- tags: [experimental-design, HITL, user-study, instructions, speed-accuracy-tradeoff, confound, annotator-guide]

## 要点
- 主要評価が作業時間(効率)の実験で、教示に速度の話を入れると、被験者は「速さ—精度」のどちらかを意識して**トレードオフの位置を動かす**。
  「速く」と書けば精度が落ち、「速さは競いません」と書けば「ゆっくり丁寧に」へ寄る。どちらの向きでも条件間比較の前提(自然なペース)を壊す交絡になる。
- 標準は**速さには触れず、目標精度だけを一貫して示す**。ペースについて書くなら「いつも通りのペースで」程度の中立表現に留める。
- 教示を中立にしても、**画面に常時出ている経過タイマーは暗黙の速度教示**(見えていれば急ぐ)。本番セッションでは計測は続けたまま表示を消し、進捗(3/10)だけ出すのが教示と整合する。
- 精度目標は操作として具体的に書く: 「縁を確認」のような曖昧な動作指示でなく「**提案が大体合っていてもピクセル単位で模範解答を目指す**」のように到達点を示す。

## 適用場面 / 状況
- HITL アノテーション効率研究など、作業時間を主要評価にし品質を副次/非劣性で見る被験者内実験。
- 教示モーダル・サイドバー・チュートリアル・配布ガイドなど、被験者が目にする文面を作る/直すとき。
- 本プロジェクトでは、ユーザー(研究者)から「『速さは競いません』をわざわざ書くのは良くないのでは?」と指摘されて気づいた(2026-09-20)。

## 内容
1. 教示の内容は「何を・どの精度まで」だけにする。例: 「提案があれば修正、無ければゼロから描く。どちらも練習で見た模範解答と同じように。提案が大体合っていても、ピクセル単位で正解を目指す」。
2. 速度に関する文(「速さは競いません」「焦らず」「作業時間は効率の指標として記録されます」)は**全部削除**し、必要なら「いつも通りのペースで」に置換する。
   出現箇所は複数ファイルに散るので、置換は `count==1` を assert する一括スクリプトで行い、事後に `grep "速さ\|焦"` で残り 0 件を確認する。
3. 「作業時間は記録されます」は同意説明として残してよいが、「効率の指標として」のような**評価の意味づけは外す**。
4. タイマー表示は練習/本番で分けて考える: 本番は非表示(計測継続)、練習は所要感覚を掴むために出してもよい。決めたら教示と表示が矛盾しないか見直す。

## 注意点・落とし穴
- 「速さは競いません」は親切に見えて、被験者に「じゃあ丁寧に」という方向づけを与える。**良かれと思って書いた一文が交絡**になる典型。
- 被験者向け文面は UI(モーダル・サイドバー・チュートリアル)と配布ガイドの両方にあるので、片方だけ直すと矛盾が出る。
- 精度目標の表現(「模範解答」「ピクセル単位」)は全箇所で同じ語にする。表現が揺れると被験者は「どっちが基準か」を推測し始める。

## 追記 (2026-09-20)
- 出典: Experimental_record/20260920.md
- 可視タイマーの非表示はユーザー承認のうえ実装した。実装パターン: **計測コードは一切触らず、表示だけを CSS の body クラスで切る**。
  `body:not(.dev-metrics) #timer, body:not(.dev-metrics) #metrics-section { display:none }` を置き、セッション開始時に
  `document.body.classList.toggle("dev-metrics", annotator === "test")` で開発用アカウントだけ表示する。
  こうすると `duration_sec`・heartbeat・フォーカス喪失の一時停止など計時側の挙動が test/本番で完全に同一になり、比較アームの対称性を壊さない
  (Knowledge/symmetric-instrumentation-across-comparison-arms.md)。
- 非表示にするのは「速度の手がかり」(経過時間・クリック数・頂点操作数のライブカウンタ)だけ。**進捗(3/10)は残す**: 残枚数の見通しは疲労・中断の判断に
  必要で、速度教示にはならない。
- 練習/本番で表示を分けず、アカウント基準で一律に非表示にした。「練習だけ表示」は教示(いつも通りのペースで)と表示の不整合を生む。
- 忘れやすい副作用: チュートリアルの画面図(SVG 内の `00:42` 表示)や配布ガイドの「作業時間は記録されます」の文にもタイマーの痕跡が残る。
  UI を消したら**説明資料側の画面描写も同時に更新**し、「記録されるが画面には表示されない」と明記する。

## 追記 (2026-09-20) — 教示文は効果量を動かす: pilot の前後比較で「良い提案の仕上げ工数」が約 2 倍になった
- 参照: Experimental_record/20260920.md(Session 3 の監査)
- 旧教示(「提案が合って見えても縁を確認」+ 経過タイマー表示)の Session 1–2 と、新教示(「提案が大体合っていてもピクセル単位で模範解答を目指す」+
  速度言及なし)の Session 3 を同一被験者(test)で比較すると、**n≥64 の提案画像で眼瞼の移動頂点数 24.5・17.5 → 38.5、眼瞼時間 40〜51 → 87 s、
  合計 62〜78 → 101 s**。n=64 は提案 ASSD 2.71 → 65 点動かして 2.11 px、n=128 は 12 点・59 s で 1.61 px と、「n が上がると仕上げコストが下がる」
  差が教示によって初めて見える形になった。
- 含意: 精度目標の書き方は**主要評価(時間)の効果量そのものを変える**。①データ収集前に教示の版を確定し、以後は文言を変えない、
  ②論文の Methods に教示の全文(または版)を載せる、③pilot データは教示版が混在するので本番解析に混ぜない(`test_` 接頭辞で除外)。
- pilot の前後比較は 1 名・各 n 2〜3 枚で、平滑化した提案・時間帯(深夜/夕方)・疲労も同時に変わっているため因果は断定できない。
  「教示が効いた方向は意図どおり」の確認にとどめ、効果の大きさは本番で見る。
