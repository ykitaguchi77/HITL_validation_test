# pilot データが数十件たまったら「事前登録の検出力が仮定した分散・効果量」を実測値に置き換えて再計算する(探索実行は登録用 CSV を上書きしない)

- type: technique
- created: 2026-09-20
- tags: [power-analysis, pilot, pre-registration, mixed-effects, user-study, HITL, non-inferiority]

## 要点
事前登録の検出力は「残差 SD 0.5・効果 −5%/倍増」のような**仮定値**で計算してある。被験者外(開発者・test アカウント)の
pilot が 20〜30 観測たまった時点で、**本解析と同じ式**(`log(duration) ~ log2n + 共変量`)を当てて残差 SD と傾きを実測し、
その値を検出力シミュレーションの引数に入れ直す。「6 名で足りるか」という質問には、仮定値ではなく実測値で答える。
ただし検出力スクリプトの出力先が登録用ファイルと同じなら、**探索的実行が登録用の表を上書きする**ので、先に出力先を分ける。

## 適用場面 / 状況
- 事前登録(OSF 等)の提出前で、被験者本人以外の pilot 記録が数セッション分ある。
- ユーザーから「この程度のばらつきで N 名は統計的に問題ないか」と聞かれた。
- 本プロジェクト: test アカウントの Session 1〜3(30 枚: 手動 10 + 提案 20)で実測 → `scripts/analysis/power_sim.py` に代入(2026-09-20)。

## 内容
1. **実測は本解析と同じ式で**: pilot が 1 名なら被験者効果は落とし、`log_dur ~ log2n + gaze + C(session)` の OLS で
   傾き(効果量)と `sqrt(mse_resid)`(残差 SD)を取る。手動群は別に `~ gaze + C(session)` で残差 SD と幾何平均。
   品質側は `assd ~ C(n) + gaze` で構造別の残差 SD と、手動 → 最高 n の平均差。
2. **実測値を検出力の引数に**: `power_sim.py --ratio <実測より弱い値も含める> --sigma <実測, 実測×1.4> --assd-sd <構造別> --assd-delta <手動 ASSD × 0.5>`。
   効果量は実測そのものではなく「実測の 1/2・1/4」でも検出できるかを見る(pilot は開発者で操作が速く、効果は過大になりやすい)。
3. **構造別に判定する**: 本プロジェクトでは眼瞼 ASSD 残差 0.76 px・瞳孔 1.79 px に対し**虹彩 3.11 px**(隠れた部分を含む楕円の解釈差)。
   同じ「inter-rater × 0.5」マージンでは虹彩だけ検出力 0.65(真差 1 px)に落ちる → **マージン規則を構造別に変えるか探索的扱いにするかを登録前に決める**。
4. **割り引く点を明示して答える**: pilot 1 名(被験者間分散は未観測・仮定値のまま)、他被験者は残差 SD が大きめになり得る、
   被験者 6 名は変量効果の下限付近(退化時の固定効果切替は計画どおり)。
5. **出力先の分離**: 登録用の表は既定設定で生成した `outputs/analysis/power_sim.csv`。探索実行の前に `--out` を用意するか、
   実行後に既定設定で再生成して復元し、復元完了を確認してから登録に添付する。

## 注意点・落とし穴
- `power_sim.py` の出力先が固定だったため、探索実行(虹彩相当 SD 3.1)が登録用 CSV を上書きした。復元ジョブをバックグラウンドで
  起動したが、セッション終了時点で未完了 → 「復元されたか」を次セッションの残件にした。**上書き先が凍結成果物なら実行前に退避する**。
- 実測した検出力の値を「計画書に追記する」と伝えるだけで終わると未固定のまま残る。転記まで同一セッションで済ませるか、残件に明記する。
- pilot の効果量(−12%/倍増、手動→n=128 で比 0.50)は教示版・提案版が途中で変わった 3 セッションの合算なので、効果量そのものより
  「残差 SD」を主に使い、効果量は保守的側で検出力を見る。

## 追記 (2026-09-20)
- 出典: Experimental_record/20260920.md(「登録用 `power_sim.csv` の復元完了を確認し … §5.11 に追記」)
- 復元は「ジョブが exit 0 で終わった」ではなく、**復元後の表を登録済みの数値と突き合わせて閉じる**(比 0.7 × SD 0.5 = 0.987 ≒ 登録値 0.99、
  H2 真差 0.3 px = 0.957 ≒ 0.96。300 反復なら検出力は 1/300 刻みなので、桁が合えば同一設定で再生成されたと判断できる)。
  探索実行で入った行(虹彩相当 δ=2.3 px)が消えていることも見る。
- pilot 実測の転記先は**計画書の検出力段落の直後に「パイロット実測」として 1 項目追加**する形にし、§6 の事前固定パラメータ(δ_k・登録用検出力)は触らない。
  実測は「仮定の妥当性の裏付け」であって固定パラメータの変更ではないので、版番号は上げず、マージン規則を実際に変える時点でまとめて改訂履歴に書く。
- 「復元ジョブ完了 → 値の確認 → 転記」を通知受領の同じターンで 1 コマンドにまとめると、前ターンで「残件」にした 2 件を取りこぼさずに閉じられる。
