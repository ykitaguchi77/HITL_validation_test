# HITL/インタラクティブセグメンテーションの効率評価で使われる計測項目(既報サーベイ)

- type: reference
- created: 2026-07-11
- tags: [HITL, annotation, metrics, evaluation, literature, segmentation]

## 概要
医用画像セグメンテーションの HITL(モデル支援・インタラクティブ)アノテーション効率研究で、
既報がアノテーション作業の評価に使う計測項目を deep-research(25主張を3-0全会一致検証・一次情報源19件)で
網羅調査した結果。客観的操作ログ(時間・クリック・マウス移動・頂点/図形編集・undo/redo・zoom/pan)と
重なり品質(Dice/IoU・correction Dice)を既に取っている実験で、**追加で取るべき項目**を欠落5系統として整理する。

## 欠落5系統(既報での定義・出典つき)

### ① 主観的作業負荷(最も一貫して併用される欠落・最優先)
- **NASA-TLX(Task Load Index)**: 6下位尺度(精神的/身体的/時間的要求・達成度・努力・フラストレーション、各0–20)。
  加重版は15対の重み付け質問を伴う。MONet(Asad et al., MICCAI 2023)は加重 NASA-TLX で**作業負荷24.67%削減**を主指標に
  (5枚目の後と最後の2回実施)。SW-FastEdit(Hadlich et al. 2023)・Vision6D(2025, 11名)でも使用。
- **SUS(System Usability Scale)**: 10項目の標準ツール使いやすさ尺度。Vision6D が NASA-TLX と併用。
- Budd/Kainz サーベイ(Medical Image Analysis 71, 2021)は「時間**と**精神的努力」が HITL 評価の2大量と明言。
- 取得法: 各条件の後に短フォームで回答させるだけ。最も安価に埋まる欠落。

### ② 境界距離の品質指標(査読者が不在を指摘する)
- Dice/IoU は重なりを見るが**境界の正確さを見落とす**ため併記が標準化。
- **HD95**(95パーセンタイル Hausdorff 距離)・**ASSD**(平均対称表面距離)・**Surface Dice at tolerance**(許容幅内の境界一致率)。
- MONet は Dice+ASSD、口腔咽頭3D研究(Sci Rep 2025)は DSC+ASSD+HD95+SDSC@1mm、MICCAI 2025 SAMUSA 査読者が Hausdorff 追加を明示推奨。
- **注意**: 元は3Dボクセルの物理間隔(mm)前提 → 2D ピクセル画像には**ピクセル許容幅への読替**が必要。
- 実装: 保存済みポリゴン/マスクから**オフライン計算でき UI 変更不要**。

### ③ アノテータ間/内の一致度
- **ICC**(級内相関)・**読影者間ペアワイズ Dice**・**test-retest 再現性**。
- IJCARS 2024 CT病変研究: ICC(手動0.80 vs AI支援0.84、小病変で0.31→0.77)と読影者間 Dice。
- Vision6D: 11名が各10サンプルを**ランダム順で3回**アノテートし試行間ペア比較で個人間ばらつき+個人内一貫性を定量化。
- **注意**: 一部画像を複数回/複数人に反復アノテートする**反復設計が必要でコスト高**。

### ④ 品質正規化した労力(効率指標のフィールド標準)
- 生のクリック数でなく**目標品質に到達するまでの労力**で測る。
- **NoC@IoU**: 目標 IoU(例90%)到達に要するクリック数(上限20)。RClicks(NeurIPS 2024)が NoC20@90 を定義。
- **Dice-vs-クリック数曲線**・IoU 面積下値。
- RClicks 補足: 中心クリック仮定は実労力を**5〜29%過小評価**、ユーザー群間で時間が**3〜79%変動**。
- **注意**: シミュレートクリック+クリック修正ワークフロー前提。ポリゴン頂点修正(1ドラッグ>1クリックの品質変化)には翻訳が必要。
  → **編集ごとにタイムスタンプを打てば「修正労力 vs 品質」曲線**としてエンドポイント値より情報量の多い報告が可能。

### ⑤ 実験デザイン上の交絡対策(計測というより設計)
- **ウォッシュアウト期間**(学習・記憶効果対策): Hi-Seg(2026 preprint)は支援/手動条件間に**4週間**。
- **提示順ランダム化**。
- **オートメーションバイアス**の測定: 誤った初期予測が最終アノテーションを引きずるか。脳動脈瘤読影(Radiol Med 2025)は
  偽陽性 AI 提示の有無で読影者評価を比較し FP が疑いを有意に上げると実証(p=0.01)。
  → **低データモデル(100〜500枚)の誤予測を初期提示する設計では実在の脅威**。専用解析または対照条件の価値あり。

## 追加実装の推奨優先順位(ブラウザ webapp 想定・後付け可能な順)
1. **NASA-TLX**(必要なら SUS も) — 低コスト(条件後フォーム)・最も一貫して報告・査読で強い
2. **境界距離**(HD95/ASSD/Surface-Dice) — 低コスト(保存済ポリゴンからオフライン)・UI変更不要・ピクセル許容幅への読替が必要
3. **品質 vs 労力曲線**(Dice-vs-クリック / 修正 Dice-vs-時間) — 低〜中(編集ごとタイムスタンプ)・フィールド標準の NoC 枠組み
4. **アノテータ間/内一致**(反復アノテーション) — 中〜高(反復設計)・実験コスト増
5. **受動ログ**(アイドル時間・初動時間・キーボード操作数・修正の FP/FN 分類) — 低(即追加可)・FP/FN は correction-Dice/area_change から部分導出可

## 適用場面
- 本プロジェクト(眼瞼/虹彩/瞳孔 HITL 効率比較)の計測項目を既報基準で強化するとき。
- 他の医用アノテーション効率研究の計測設計・査読対応のチェックリストとして。
- 注意: 客観的操作ログ(undo/redo・zoom/pan・マウス移動距離)は多くのベンチマークが人間計測せずシミュレートクリックのみである点で
  むしろ先行。埋めるべきは「人的要因(主観負荷)」と「境界品質」であり、クリックシミュレーションを増やす方向ではない。

## 本プロジェクトへの適用判断(2026-07-11)
既報の一般論を、本実験(眼瞼/虹彩/瞳孔 HITL・盲検 condition-mixed・被験者内)へ翻訳して確定した実装方針。
**「重い定番指標をそのまま入れる」のではなく、実験構成の制約から軽量な等価物へ翻訳する**のがポイント。

- **主観負荷: フル NASA-TLX ではなく Paas 単一項目尺度**。本実験は **8つの HITL セッションが condition-mixed**
  (1セッション10枚に seg100〜2500 が混在、`prepare_experiment.py`)のため、**主観負荷は画像ごとに取るしかない**
  (セッション末一括では盲検混在でどの条件か切り分け不能)。フル NASA-TLX(加重版で1枚2〜3分)はアノテーションより
  長く非現実的 → **Paas の9段階メンタルエフォート単一項目**(1問約5秒)を全画像で。**submit(タイマー停止)後に分離**
  回答させ作業時間に混入させない。**教訓: 被験者内×条件混在×盲検 なら「条件ごと集計」が封じられ、多次元TLX より
  単一項目を毎試行の方が設計に合う**。
- **境界距離: 3px 固定・眼瞼のみ**。2Dピクセル空間の許容幅は臨床的に **3px**(1〜2pxズレは許容)。**眼瞼のみ**なら
  構造サイズでのスケール不要=固定3pxで統一(小構造ほど厳しくの悩みが消える)。HD95/ASSD/Boundary-F1@3px を
  **保存済みポリゴンからオフライン計算**(UI変更不要)。
- **NoC の翻訳**: クリック方式の NoC@IoU は頂点ドラッグ方式に直接使えない → **編集イベントごとのタイムスタンプ**で
  「Dice到達までの編集数/秒」= 修正労力 vs 品質曲線に置換。
- **オートメーションバイアスは後付け解析で足りる**(専用対照条件は不要): (a) scratch をアンカー無し基準に最終Dice比較、
  (b) 最終 GT 一致度が初期予測品質に相関するか(既存 `correction_dice`・`area_change` と最終Diceから)で引きずりを直接検出。
- **再現性は個人内を優先**: 後半セッションに5枚程度の**同一条件再掲**で test-retest(ICC/ペアワイズDice)。個人間一致は
  Latin方格で同一画像を3人が見るが**条件が3人で異なり交絡**するため個人内を優先。

## 更新 (2026-07-11)
- 出典: Experimental_record/20260711.md
- **許容幅は 3px → 2px に最終変更**(ユーザー判断「3px 以上は意味のある実誤差、2px 以内を一致」)。
  最終仕様: 眼瞼のみ・Boundary-F1(Surface Dice)@2px・HD95/ASSD は生の px 距離で併記。
- **5系統すべて実装完了・end-to-end 検証済み**: ①Paas 9段階単一項目(全画像・submit後)②境界指標@2px
  (cv2.distanceTransform 実装 → [[boundary-metrics-2d-cv2-distancetransform]])③編集イベントの
  タイムスタンプ `events[]` + 初動/アイドル時間 ④再掲5枚の Session 9(専用RNG → [[seeded-design-additive-change-dedicated-rng]])
  ⑤オートメーションバイアスは後付け解析のまま(実装なし)。
- **主観負荷の計測タイミングの実装知見**: submit 押下で「metrics スナップショット(duration 確定)→タイマー停止→
  努力尺度モーダル」の順に処理すると、回答時間が作業時間に混入しない。尺度は submit 後に出す UI でも
  **duration の確定を必ずモーダル表示より前に**行うのが要点。
- **境界指標を眼瞼のみ→全3クラス(eyelid/iris/pupil)へ拡張**。オフライン計算でアノテーター負担ゼロのため絞る理由が無い。
  楕円(iris/pupil)も**マスクにラスタライズしてマスク境界のずれ**を測る(パラメータ直接比較ではない)。列は per-class 共通
  `{k}_hd95`/`{k}_assd`/`{k}_boundary_f1`。楕円は HD95/ASSD が有用、Boundary-F1@2px は固定許容幅ゆえ小さい瞳孔ほど甘め。
- **Paas 尺度の目盛りは 1–9 で確定**(0–10 の臨床NRSも検討したが、「Paas(1992)=検証済み尺度」として論文引用できる利点を優先)。
  単一項目の妥当性は「1問で主観的努力を聞く」構成にあり、目盛り数は混合効果モデルの連続量扱いにほぼ影響しない。
