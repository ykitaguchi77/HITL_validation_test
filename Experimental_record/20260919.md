### Explore ②(few_shot_HITL 側の LoRA 資産)の要点 — 移植計画の前提
- **モデル**: SAM 2.1 Hiera-Large(HF transformers `facebook/sam2.1-hiera-large`)。LoRA は mask decoder 内の全 `nn.Linear` に r=8/alpha=16
  (`scripts/eyelid_matting/sam2_decoder_head.py`)。encoder/prompt encoder 凍結、**プロンプト無し**(空点 label −1)で mask token 0 の 256×256 logit を出力。
  構造(eyelid/iris/pupil/caruncle)ごとに**別 LoRA**(shared frozen encoder + shared base decoder + structure-specific LoRA、≈230k params ≈1 MB/構造)
- **推論パイプライン**: `Sam2Segmenter.set_image` → FPN 3 レベル特徴(fp16 npz キャッシュ `FeatStore`)→ `build_decoder_head(mode="lora")` →
  `predict_prob256` → `postprocess_prob`(resize・≥0.5・最大連結成分・`mask_to_polygon`)。本 webapp の出力契約 `{channel: 512×512 uint8 mask}` に合わせやすい
- **学習 API**: cold start `train_decoder_multi(...,epochs=80)`(内部 20% val・**≥4 枚必須**)、warm start `ContinualDecoderTrainer(lr=1e-3).add(store, ids).train(E)`
  (AdamW 状態保持・val 無し・最終 epoch 採用)。推奨レシピは **n<32: 2 epoch/枚、n≥32: 1 epoch/枚**(E2→K64)。**n=1, 2 は未検証**
- **重大な欠落**: **decoder-LoRA の重みはどこにも `torch.save` されていない**(`trainable_state()` で in-memory 再ロードのみ)。
  固定チェックポイント n=1..128 は**未生成**。生成には `ContinualDecoderTrainer` を未学習 `build_decoder_head("lora")` から回し各 n で
  `torch.save(trainer.model.trainable_state(), ...)` を足す必要(最も近い CLI: `scripts/eval/incremental_lora.py`、指標のみ出力)。
  学習順は `outputs/20260919_joint_decoder/tables/orders.json` の `train_order`(128 枚・患者層化ランダム・seed 0)
- **精度(separate decoder-LoRA cold start, n=8/16/32/64/128)**: eyelid Dice 0.951/0.961/0.963/0.968/0.970(ASSD 5.65→3.18 px)、
  iris 0.796/0.838/0.896/0.925/0.937(ASSD 29.2→7.6)、pupil 0.782/0.740/0.838/0.868/0.905。小 n(eyelid): n=4 Dice 0.945/ASSD 6.36。
  参照線: inter-rater Dice 0.9733 / ASSD 2.30 px / HD95 7.81 / BF@2px 0.69(ユーザー 27 枚 vs CVAT Eyelid∪Caruncle)
- **held-out プール**: 未使用 2,625 枚 / 190 患者だが**患者分離は未実施**(eval 98 患者中 67 が train 128 枚の患者と重複)→ 本研究の
  「患者リーク無し」方針に合わせて学習順・評価・被験者用画像の患者分離を組み直す必要あり
- **環境・速度**: `Eyelid_few_shot_HITL/.venv`(Python 3.13.5・torch 2.12.1+cu126・transformers 4.57.3、RTX 3080 Ti 16 GB)。
  Hiera-L encoder ≈0.1 s/枚 GPU(CPU 5.1 s)、LoRA 推論 0.04 s/枚/構造、cold start n=128 ≈3 min GPU、GPU 使用 1.7〜2.6 GB
- few_shot 側の `scripts/annotation_app/`(本 webapp からの派生・単一ユーザー・eyelid 1 クラス)の推論は CNN head + 境界プロンプトで
  **decoder-LoRA ではない** → 本 webapp に LoRA 推論を移植する方針(ユーザー確定済み)で問題なし

### 設計仕様(計画ファイルに記述した確定案)
- 条件: n ∈ {0(手動), 1, 2, 4, 8, 16, 32, 64, 128}。n≥1 は固定チェックポイントの提案(オンライン学習は被験者で回さない)。
  1 枚では eyelid / iris / pupil の 3 構造に**同じ n** の構造別 LoRA を使う(caruncle は eyelid に統合)。素の SAM 条件は置かない(prior-prompt SAM Dice 0.53 をモデル指標として示す)。
- 保留だった 2 点の決定:
  - **学習レシピ**: n=0 から 1 枚ずつ追加・**各 1 epoch で統一**(lr 1e-3、AdamW 状態保持、flip aug)。few_shot 側推奨の「n<32 は 2 epoch」は採らず、
    n で epoch を変えない。理由 = 「実運用でユーザーが回す手順そのもの」にして「後ろ向きシミュレーションが実運用の手間を予測する」主張と整合させるため。
  - **1 人あたり構成**: 練習 5 枚(手動 2 + 提案あり 3、GT オーバーレイ + Dice 表示、解析除外)+ **本番 10 セッション × 10 枚 = 100 枚**。
    各セッション = n∈{1,…,128} の 8 条件 1 枚ずつ + 手動 2 枚、提示順ランダム・n 非表示 → 手動 20 + 提案あり 80(各 n 10 枚)、約 2〜3 時間・複数日分割可・戻れない進行。
    現行の「再掲セッション」「scratch 2 回目」は**廃止**(各セッションに散らした手動アンカーが順序効果とベースラインを担う)。
- 画像・割付: 100 枚 = 10 グループ × 10 枚(各グループ 正面 7 + 周辺 3、周辺位置を巡回ずらし → 各セッション・各条件とも 7+3)。
  条件スロット 10 個(n×8 + 手動×2)、被験者 a・グループ g の条件 = `slot[(g + 3a) mod 10]` → 各画像は 3 名で異なる 3 条件(Latin 長方形)。画像→セッション対応は被験者ごとに seed 付きシャッフル。
- 評価: 主要 = 品質ゲート合格アノテの 1 枚あたり active 時間(`duration_sec` 現行定義)。副次 = 不合格率・頂点移動数・クリック数・無修正受入率・Paas effort・
  対 GT ASSD/HD95/BF@2px(Dice 併記)・クラス別修正量。天井 = 手動アンカー(3 名 × 20 枚)と CVAT GT の一致。
  解析 `log(duration) ~ log2(n) + gaze + order + session + seed + (1|annotator) + (1|image)`(n≥1)、手動 vs 各 n は事前対比(Holm)、飽和は `a + b·exp(−n/τ)` を AIC 比較。
- OSF: `osf.io/d7e2g` は凍結のため、設計確定後に**新規登録(v2)**を出し、v1 からの変更理由(データ収集前のモデルバックエンド変更)を明記。IRB 19492-7 の範囲内という前提は不変。
