## HITL アノテーション webapp の実装

### 概要
眼瞼HITLアノテーション実験用の webapp を新規実装した（`PLAN.md` 準拠）。
CVAT風UIで、ゼロから / 各SegFormerサブセットモデルをベースにしたHITLの
アノテーション効率（Dice・所要時間・クリック数・マウス移動距離・クラス別修正量）を計測する。
バックエンド（FastAPI + PyTorch推論）とフロント（Konva.js, ビルド不要）を実装し、
Playwright + API テストで end-to-end 検証済み。

### 設計判断（ユーザ確認済み）
- 技術スタック: FastAPI（推論バックエンド）+ Konva.js（CDN・素のJS・ビルド不要）
- アノテーション4クラス: Eyelid/Caruncle（polygon）, Iris/Pupil（楕円OBB）
- HITL時、モデルは Eyelid/Iris/Pupil を初期提示。**Caruncle はモデル非対応**
  （SegFormerは3ch=Eyelid+Caruncle統合）のため毎回手動追加。GTには Caruncle が別ラベルで存在。
- スコープ: webapp優先。モデルは `experiment.json` の `models.*.path` で差し替え可能。
  現状は全phaseが full 3000枚チェックポイントのプレースホルダ。
- 画像割当: testセット 2500-2999 から **60枚すべて異なる画像**（症例リーク無し）を各phaseに10枚ずつ。

### ハマった点と解決策
- 問題: `image_metadata.csv` は ids 0-1999 のみ（系統A）で test範囲 2500-2999 を含まない。
  解決策: CVAT XML（`eyelid_caruncle_seg_0-3000.xml`）から直接 id/name を取得し、
  patient_id はファイル名先頭（最初の`-`前）から導出。症例安全 test pool 463枚を確保。
- 問題: SegFormerチェックポイントは `decode_head.classifier` が150→3chでMISMATCH警告。
  解決策: `from_pretrained(..., num_labels=3, ignore_mismatched_sizes=True)` 後に
  `ckpt["model"]` をload_state_dict。head は学習済み重みで上書きされ正常動作。
- 問題: Playwright の合成 MouseEvent/PointerEvent が Konva のポインタ処理に届かず描画/パンを実イベントで検証できない。
  解決策: `HITL.app` をデバッグ用に公開し、`stage.getPointerPosition` を上書きして
  コントローラの `_down/_move/_up` を直接駆動して単体検証。

## webapp ドラッグ/楕円編集の修正 と Stop hook の文字化け修正

### 概要
ユーザ報告に基づき、(1) 画像のドラッグ移動、(2) 楕円アノテーションのリサイズ/回転、
(3) 楕円ハンドルの拡大率非依存化 を修正。さらに「Knowledge/Experiment が更新されない」
との指摘から **Stop hook が毎回発火するが JSON 解析に失敗していた**根本原因を特定・修正した。
各修正はヘッドレス Playwright（実コードをローカルサーバで読み込み）で検証済み。

### 変更ファイル
- `scripts/webapp/static/js/tools.js` (編集) — 選択ツールのドラッグ判定を再設計
- `scripts/webapp/static/js/canvas.js` (編集) — Transformer を layer に移設・ハンドル拡大
- `.claude/hooks/record-session.ps1` (編集) — stdin を UTF-8 固定で読むよう修正
- `C:\Users\CorneAI\Downloads\CLAUDE_experiment._windows.md` (編集) — 自己展開テンプレートの
  hook にも同じ UTF-8 修正を反映（v1.0→v1.1）

### 1. 画像ドラッグ（パン）が効かない
- 症状: ポリゴンを外した状態で画像をドラッグしても全体が動かない。
- 原因: Eyelid ポリゴンや Iris/Pupil の塗りが画像をほぼ覆い、「画像」を掴んだつもりが
  図形本体（`onShape=true`）を掴んでおり、旧パン条件 `!onShape` が偽になっていた。
- 修正: mousedown では選択せず press を保留。ドラッグ時は「**選択中図形の編集ハンドル**
  （選択ポリゴンの頂点 / 選択楕円の本体）を掴んだ時だけ編集、それ以外は常にパン」へ変更。
  クリック（非ドラッグ）時のみ図形選択 / 空白で選択解除。

### 2. 楕円のリサイズ/回転ができない
- 原因: `Konva.Transformer` のアンカー/回転ハンドルは「頂点でも図形本体でもない」ため、
  1 のパンロジックに落ちてドラッグがパンに化けていた（tools.js は Transformer 非考慮）。
- 修正: `_down` で「押下対象の親が `Konva.Transformer` なら return（Konva に委譲）」を追加。
  これでリサイズ・回転・本体ドラッグ移動がすべて機能。

### 3. ハンドルが拡大率でサイズ変化／小さくて掴みにくい
- 原因: Transformer をスケールされる world グループ内に置き、毎ズーム `anchorSize(16/s)` で
  打ち消していたため再計算タイミングでブレた。
- 修正: Transformer を**スケールされない layer に移設**し、`anchorSize` 等を画面px定数で固定。
  ズーム後は `transformer.forceUpdate()` でノードへ追従。アンカーは ~10px→~16px に拡大。

### 4. Stop hook が記録を書かない（最大の発見）
- 症状: `record.log` に毎ターン `stop-hook fired` → `JSON parse failed` →
  `transcript_path 不明（記録不可）` が並び、記録用 `claude -p` が一度も起動していなかった。
- 真因: フックは正常発火していたが、`[Console]::In.ReadToEnd()` が UTF-8 の stdin を
  **コンソール既定コードページ(CP932)で誤デコード**。JSON 内の `last_assistant_message`
  の日本語が壊れ、多バイト境界のズレで構造文字を飲み込み `ConvertFrom-Json` が失敗していた。
  （当初 BOM を疑ったが、診断ログで生 stdin に BOM 無し・日本語が化けていることを確認して確定）
- 修正: `[Console]::OpenStandardInput()` を UTF-8 の `StreamReader` で読むよう変更。
  PowerShell 5.1 で再現テスト（同一の `(114)` エラー）→ 修正版で解析成功を確認。

### 検証
- ヘッドレス Playwright（`chromium_headless_shell-1208` を `executablePath` 指定で利用、
  静的ファイルを `python -m http.server` で配信）で実 `canvas.js`/`tools.js` を読み込み:
  - 何も選択せずポリゴン面上をドラッグ → world が増分どおり移動・選択なし維持
  - クリックで図形選択、選択中の余白ドラッグはパン（選択維持）
  - 楕円: アンカーでリサイズ（rx/ry 拡大・world 不動）、回転ハンドルで回転、本体で移動
  - アンカー実サイズが scale 0.59〜4.57 で 17.5px 一定
- Stop hook: PowerShell 5.1 で `[Console]::In` 方式は実フックと同一エラーで失敗、
  `OpenStandardInput`+UTF8 方式は `ConvertFrom-Json` 成功を確認。

### ハマった点と解決策
- 問題: pan ロジックは単体ハーネスでは元から動作しており、コード読みでは原因が見えなかった。
  解決策: 実 app と同条件（図形が画像を覆う状況）を Playwright で再現し、`onShape` が
  パンを阻害していると特定。
- 問題: hook の失敗が「BOM か CP932 か」切り分け困難。
  解決策: フックに生 stdin 保存＋例外メッセージ/先頭200字のログを追加し、`last-stdin.txt` の
  化け方とエラー位置(1993)から CP932 誤デコードと断定。

## webapp ポリゴン点追加モード・塗りつぶし切替の追加

### 概要
上記の修正に続き、ユーザフィードバックに基づき編集UIをさらに3件改善:
(1) 選択中ポリゴンへの「点追加（統合）モード」、(2) 点追加中の頂点丸マーカー表示、
(3) 塗りつぶし（中の色）ON/OFF トグルボタン。各回ヘッドレス Playwright で実コード検証。

### 変更ファイル
- `scripts/webapp/static/js/tools.js` (編集) — 点追加（extend）モード一式・マーカー表示
- `scripts/webapp/static/js/canvas.js` (編集) — `applyFill`・`showFill` 状態・楕円/多角形の塗り制御
- `scripts/webapp/static/js/app.js` (編集) — 🎨 塗り切替ボタンの配線
- `scripts/webapp/static/index.html` (編集) — 🎨 ボタン追加
- `scripts/webapp/static/css/style.css` (編集) — 🎨 ボタンの `.active` ハイライト

### 1. 選択中ポリゴンへの点追加モード（extend）
- 要件変遷: 当初「Shift+クリックで**新規**別ポリゴンを作成」と実装したが、ユーザの真意は
  「**選択中の既存ポリゴンに点を追加（統合）していく**」だったため作り直した。
- 挙動: ポリゴン**選択中のみ** `Shift+クリック` で extend モード開始（未選択時は無反応＝新規図形を作らない）。
  追加点はその既存ポリゴンの頂点列に追記され**図形数は増えない**。通常クリックで追加継続、
  **ダブルクリック/Enter で確定**（確定後も選択・編集可）、**Esc で追加分を破棄して原形に復元**。
- 実装: `_startExtend / _extendClick / _extendFinish / _cancelExtend` を追加。`_down/_move/_up/_dbl/_key`
  と `_cancelDraft`（ツール切替時のキャンセル）に配線。
- ハマり: Playwright が `dblclick` を2つの `mouseup` の**間**に発火し、末尾 `_up` が確定後に
  走って選択解除してしまう（`down1,up1,down2,dbl,up2` の順）。`_dbl` で立て次の `_down` で解除する
  **ワンショットガード**で実ブラウザ順序とも両立させて解消。

### 2. 点追加中の頂点丸マーカー
- 原因: extend モード開始時に `shape.setEditable(false)` を呼ぶため**頂点の丸が全部消え**、
  点を追加している最中に丸が見えなかった。
- 修正: 描画ツール同様、extend 中は各頂点に丸マーカーを生成・追加（`_startExtend`/`_extendClick`）、
  確定/取消で破棄して実アンカーに戻す（`_extendFinish`/`_cancelExtend`）。ズーム時も画面px一定にリスケール。

### 3. 塗りつぶし（中の色）ON/OFF トグル
- 要件: マスクの表示/非表示とは**別に**、内部の塗り（薄い色）を塗るか塗らないかを切替えたい。
- 実装: ツールバーに 🎨 ボタン追加。`view.showFill` に状態保持（画像切替後も維持）。
  塗りOFF時は **alpha 0（透明）だが `hasFill` は維持** → 見た目の塗りだけ消え、
  **内部クリックでの選択（hit判定）は維持**。polygon/ellipse 双方に `applyFill` を実装。
  塗りOFF中に新規作成した図形も透明で生成。ボタンは ON 時に青ハイライト（`.active`）。

### 検証（ヘッドレス Playwright・実コード）
- extend: 4点選択中→Shift+クリックで同一図形が5点（図形数1のまま）→さらに追加で7点→
  ダブルクリックで確定・選択維持・編集可、Esc で4点に復元、未選択での Shift+クリックは無反応。
- マーカー: extend 中は全頂点に丸表示（5→6個）、確定後は実アンカーに戻り pts=7 を選択解除後も保持。
- 塗り: ON=`rgba(...,0.18)` / OFF=`rgba(...,0)` / 再ON=0.18、**塗りOFFでも内部クリックで選択可能**。
