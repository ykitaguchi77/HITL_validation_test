## 盲検 Latin方格デザインへの実験再構築(prepare_experiment 再生成 + 盲検混合モード UI)

### 概要
- 前セッションで保留だった実験設計 Q2 関連の項目をユーザーと確定し、それに沿って **実験生成スクリプトと webapp を盲検実験仕様に作り直した**。
- 確定した設計: **アノテータ3名**・**GT 作成者はアノテータから除外**・**1セッション=10枚(正面7+周辺3)**・**scratch は全アノテータでセッション0固定**・**8つの HITL モデル(seg100〜2500)は盲検でランダム混合提示**・3×9 の **Latin 方格**でアノテータ×条件の提示順を均衡化。
- さらに **練習(practice)セッション**を追加: 5枚(正面3+周辺2、seg1000 で初期予測)、`is_practice=true` で解析から除外、本番と画像オーバーラップ無し、**練習でのみ GT オーバーレイ + per-class Dice を表示**(本番は GT/Dice を一切出さない)。
- 100/200/300 モデルは独立 UI フェーズではなく、8 HITL 条件のうちの3条件として組み込む形に整理。
- 全工程を実サーバ + Playwright で **end-to-end 検証**し、DOM/API のどこにも盲検リーク(モデル名・条件・ブロック)が無いことを確認した。

### 変更ファイル
- `scripts/prepare_experiment.py` (編集) — 9ブロック×10枚(正面7+周辺3)・3×9 Latin 方格・アノテータ別盲検ラン・scratch をセッション0固定・HITL 8セッションをシャッフル interleave・練習5枚(3F+2P/seg1000)生成。全 assertion PASS。
- `scripts/webapp/config/experiment.json` (生成) — 上記の確定構成を出力。正解(モデル/条件)はサーバ側にのみ保持。
- `scripts/webapp/backend/main.py` (編集) — 盲検 API(`/api/run`, `/api/session`, `/api/predict`, `/api/submit`)。クライアントへモデル/条件/ブロックを一切返さず、隠し正解は記録時にサーバ側で付与。
- `scripts/webapp/backend/inference.py` (編集) — モデルキャッシュ 4→9(8モデル提示でのスラッシング回避)。
- `scripts/webapp/backend/session.py` (編集) — 解析用カラム追加(annotator, condition, model, train_size, block, gaze, is_practice, session_index 等)。

### 変更理由
- 期待バイアス・画像難易度交絡を抑えるため、HITL モデル間を盲検ランダム混合とし、scratch のみ別建ての基準にする(scratch は構造上盲検化不可能)。
- アノテータ×条件の交絡を Latin 方格で均衡化し、混合効果モデルでの解析を可能にするため。
- 練習セッションで操作習熟と GT/Dice の感覚を与えつつ、本番では正解情報を完全に隠してバイアスを除去するため。

## プレフィル点の均等化 + 「別クラスが選択される」症状の原因特定(ブラウザキャッシュ)【完了・実機検証済み】

### 概要
- ユーザーから追加要望2点: ①プレフィルの点を**均等(等間隔)**にしてほしい、②ポリゴン選択中に別クラスの点を選択するとそちらに切り替わる症状が**改善されていない**。両方に対応・実機検証して完了。
- 結果:
  1. **プレフィルを等弧長リサンプリングに変更** → eyelid prefill が **58点・間隔ほぼ一定(spacing std 1.1px ≈ 均等)** に。曲率ベースで不均等だった前実装を置換 ✓
  2. **②はコード上は既に解消済みだった**。Playwright で実証(eyelid選択中に iris/pupil を canvas クリックしても eyelid のまま、逆も同様)。「改善されない」の真因は**ブラウザが古い JS をキャッシュ**していたこと。**no-cache ヘッダを追加**し、以降は通常リロードで最新コードが反映されるようにした ✓

### 変更ファイル
- `scripts/webapp/backend/geometry.py`(編集) — `mask_to_polygon` を曲率ベースの `cv2.approxPolyDP`(不均等)から**輪郭の等弧長リサンプリング(約14px間隔)**へ変更。eyelid prefill は約58点・等間隔(spacing std 1.1)。
- `scripts/webapp/backend/main.py`(編集) — 静的アセット(JS/CSS/HTML)に **`Cache-Control: no-cache` ヘッダ**を付与し、ブラウザが古い JS を使い続けてフロント修正が反映されない事故を防止。

### 検証結果(Playwright 実機 + 計測)
| 要望 | 結果 |
|------|------|
| ① プレフィルの点を均等に | 等弧長リサンプリングで eyelid 58点・spacing std 1.1px(≈一定)。no-cache 有効 ✓ |
| ② 別クラスが選択される症状 | コードは既に解消済みと実証(選択はサイドバーのみ・canvasクリックで切替わらない)。真因はブラウザキャッシュ → no-cache で解消 ✓ |

### ハマった点と解決策
- 問題: フロントの修正(canvasクリックで選択を切り替えない)を済ませても、ユーザー環境では「別クラスが選択される」と報告が続いた。
  - 原因: ブラウザが**旧 JS をキャッシュ**しており修正後コードがロードされていなかった(コードは正しかった)。
  - 解決策: 静的配信に **no-cache ヘッダ**を付与し、Playwright(キャッシュ無し)で現行コードの正しさを機械的に再確認。ユーザーには一度だけ Ctrl+F5(ハードリロード)を依頼。
- 教訓: 「直したのに直らない」報告は、まず**配信側キャッシュ**を疑い、キャッシュ非依存(Playwright/シークレット)で挙動を確定してから追加修正する。

## 練習1例目の GT 遅延ポップイン対策(入力ブロックオーバーレイ + モデル事前ウォームアップ + 計測タイマー後ろ倒し)【完了・実機検証済み】

### 概要
- ユーザー報告: 練習試行で **1例目だけ GroundTruth(プレフィル)が遅れて出てくる**。入力途中で GT が出るのは良くない。対策として「画像表示を遅らせる(推論中表示)」か「割り振りが決まっているなら inference label を保存して即出す」べきでは、との指摘。
- 原因: 1例目はモデルが**コールドロード**(初回推論で重み読込・初期化に数秒)するため、ユーザーが編集を始めた後にプレフィルが遅れて描画されていた。
- 対応(3点)し、実サーバ + Playwright + curl 計測で検証して完了:
  1. **推論完了まで入力ブロック** — `#loading-overlay`(z-index 30、HITL/練習は「推論中… しばらくお待ちください」、scratch は「読み込み中…」)で canvas を覆い、**画像ロード + プレフィル取得が揃ってから**解除。途中ポップイン/割り込みを防止。
  2. **起動時モデル事前ウォームアップ**(バックグラウンドスレッド) — サーバ起動時に `_warm_models()` を daemon thread で走らせ、アノテータ選択→セッション開始の操作中(数十秒)に重みをロード。検証で predict が **0.07〜0.17秒**(コールド数秒を解消)。
  3. **計測タイマーは準備完了後に開始** — `loadCurrent()` で画像 + プレフィルが揃った後に `metrics.reset()` → `_setLoading(false)` → `_startTimer()` の順にし、**推論/画像ロードの待ち時間を作業時間(duration_sec)に含めない**(計測の妥当性向上)。

### 変更ファイル
- `scripts/webapp/backend/main.py`(編集) — `_warm_models()` を追加し `threading.Thread(target=_warm_models, daemon=True, name="warm-models").start()` で起動時ウォームアップ。
- `scripts/webapp/static/index.html`(編集) — canvas 上に `<div id="loading-overlay" class="hidden">推論中…</div>` を追加。
- `scripts/webapp/static/css/style.css`(編集) — `#loading-overlay`(position:absolute; inset:0; z-index:30; flex 中央寄せ)と `.hidden` を追加。
- `scripts/webapp/static/js/app.js`(編集) — `loadCurrent()` で先に `_setLoading(true, "推論中…")` + `_clearGT()` → 画像ロード → predict → 描画 → **その後** `metrics.reset()`/`_setLoading(false)`/`_startTimer()`。`_setLoading(on,text)` ヘルパ追加。

### 検証結果(Playwright 実機 + curl 計測)
| 要望 | 結果 |
|------|------|
| 入力途中で GT が出ない | オーバーレイ(z-index 30、「推論中…」)がロード中は入力を覆い、プレフィル準備後に解除。タイマーは解除後に開始 ✓ |
| 1例目から高速 | 起動時ウォームアップで warm predict = **0.07〜0.17秒**(curl time_total)✓ |
| 計測の妥当性 | 待ち時間(推論/画像ロード)は duration に非計上 ✓ |

### 留意点

## 練習を2部構成へ再設計(Scratch → 予測修正)+「動作テスト用」メニュー追加

### 概要
- ユーザー要望を受け、セッション末尾で2点を実装。
  1. **練習を2つのウォームアップセッションに分割** — 単一の練習5枚(3F+2P/seg1000)から、**両ワークフローを必ず体験**する2部構成へ:
     - **練習1「Scratch(ゼロから描く)」**(`is_hitl=false`・model=None・正面2+周辺1=3枚)
     - **練習2「修正(予測を直す)」**(`is_hitl=true`・**seg1000** プレフィル・正面2+周辺1=3枚)
     - 周辺視を各練習に1枚入れて iris/pupil 楕円の傾き編集も練習させる。**各画像の提出後に GT(点線)を表示**(解析からは除外)。
  2. **「動作テスト用」擬似アノテータを追加** — UI のアノテータ選択に **`test`(表示名「動作テスト用(本番に含めない)」)** を追加。割当はアノテータ1と同一だが、記録は **`session_id="test_..."`(annotator="test")** として本番データと分離保存し、リハーサルが本解析を汚さないようにした。

### 変更ファイル
- `scripts/prepare_experiment.py`(編集) — `PRACTICE_SPEC` を2セッション(`p_scratch` then `p_hitl`/seg1000、各 n_f=2/n_p=1)に変更。`_audit_and_assert` も `practice order: scratch then hitl`(`is_hitl==[False, True]`)・周辺≥2 を検証。
- `scripts/webapp/config/experiment.json`(再生成) — 練習2セッション構成を出力。
- `scripts/webapp/backend/main.py`(編集) — `RUN_ALIAS={"test": ANNOTATORS[0]}`・`UI_ANNOTATORS=ANNOTATORS+["test"]`。test は中身はアノテータ1の割当を走らせ、記録だけ `test_` プレフィックス(annotator="test")で別保存。
- `scripts/webapp/static/js/app.js`(編集) — アノテータ選択ドロップダウンに `test` を追加(`a==="test"` のとき表示名「動作テスト用(本番に含めない)」)。

### 変更理由
- 本番は scratch(ゼロ描画)と HITL(予測修正)の両方を行うため、**両方の操作を事前に必ず練習**させて習熟差による交絡を減らす。
- 実験者がフローを通しで確認(リハーサル)できるよう、本番データを汚さない専用の記録経路を用意する。

### 留意点
- 練習は本番(study 90枚)と画像が非重複(`assert not (prac_ids & study_ids)`)で、`is_practice=true` により解析から除外される。
- `test` アノテータの記録は `outputs/results/test_*/` に入るため、解析時は **annotator!="test" かつ is_practice==false** で絞る。
