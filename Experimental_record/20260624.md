# 2026-06-24 実験記録

## 3名アノテータ配布のためのWebApp外部公開を実装（Cloudflare Tunnel + Basic認証 + 配布資料）【実装完了・実機検証済】

### 概要
- 06-20 に「方針提示のみ・実装は次セッション」としていた **HITL WebApp の3名配布** を本セッションで実装・検証した。
- 結論方針: デスクトップアプリ化は不向き（各端末に 8チェックポイント約430MB＋torch+CUDA＋全画像を配る必要があり、データ分散で盲検整合性が崩れる）。**GPU・モデル・画像を持つ現PCで uvicorn を起動したまま、Cloudflare Tunnel で公開し、3名はブラウザでURLを開く**構成を採用。推論はサーバ側（0.1秒程度・直列処理可）、結果は全員分が自PCの `outputs/results/` に中央集約され、盲検もサーバが担保。
- 医用画像を扱うため、TLS（Cloudflare）に加えて **HTTP Basic 認証（案A: 共有パスワード1個）** を1枚かませる構成にした。trycloudflare の URL は「知っていれば誰でも到達可能」なため、URLの不明瞭さに頼らずアクセス制御を必須とした。

### 実装したもの（変更/新規ファイル・相対パス）
- `scripts/webapp/backend/main.py`（編集） — 共有パスワード HTTP Basic 認証を追加。
  - `HITL_AUTH_PASS` 環境変数が設定されている時のみ全リクエスト（API・静的ファイル両方）を Basic 認証で保護するミドルウェア（`_no_cache` ミドルウェアの後段に追加）。
  - 未設定（localhost開発）時は従来通り認証なしで動作し、**起動時に「access control DISABLED」警告を表示**して公開時の設定忘れを防止。
  - 認証失敗時は `401` ＋ `WWW-Authenticate: Basic realm="HITL Annotation"` ヘッダを返し、ブラウザのログインダイアログを出す。
- `scripts/webapp/run_server.ps1`（新規） — サーバ＋トンネル一括起動スクリプト。先頭の `$Pass` を本番用に書き換えて実行 → 別ウィンドウで uvicorn 起動 → `cloudflared tunnel --url http://localhost:8000` で公開URLを発行。既定値のままだと警告。
- `scripts/webapp/README_deploy.md`（新規） — 管理者向け運用手順。構成図・起動/停止・URL配布・PC常時起動（スリープ無効）の注意・データ保存場所（`outputs/results/`）・セキュリティ・トラブルシュート。
- `scripts/webapp/annotator_guide.md`（新規） — アノテータ向け配布資料。ログイン → アノテータ選択 → セッション順序（練習2種 → Scratch → Session1〜8）、3クラスの描き方（まぶた=涙丘込みで一体／虹彩・瞳孔=楕円、周辺視は傾ける）、ツール操作表、提出・中断、盲検の説明。UI実機の文言・キー操作と一致させて作成。

## 運用サポート: 配布パスワード（`$Pass`）の変更箇所の案内【Q&A のみ・コード変更なし】

- ユーザーからの「`run_server.ps1` の `$Pass` はどこにあり、どう変更するか」という質問に回答（調査のみ・ファイル変更なし）。
- 場所: `scripts/webapp/run_server.ps1` の **19行目**、「認証情報」セクション内 `$Pass = "CHANGE_ME_BEFORE_SHARING"`。
- 変更方法: 19行目のダブルクォート内（既定値 `CHANGE_ME_BEFORE_SHARING`）を配布用パスワードに書き換えて保存するだけ。ユーザ名を変える場合は18行目 `$User = "annotator"` も変更可。既定値のまま実行すると警告が出て一旦停止する事故防止ガードがある旨も補足。
- アノテータには **このパスワード + ユーザ名 `annotator` + 公開URL** を配布する運用を再確認。

## バッチ起動時の文字化け＋ウィンドウ即閉じを修正（純ASCII化）【修正完了・ASCII検証済】

- ユーザー報告: `run_server.bat` をダブルクリックすると `'繧｢繝弱ユ繝ｼ繧ｷ繝ｧ繝ｳ…' は内部コマンドまたは外部コマンドとして認識されていません` のような文字化けエラーが多数出て、キーを押すとウィンドウが即座に閉じてしまう。
- 根本原因: **cmd.exe はバッチファイルを日本語コードページ（cp932）で解釈する**ため、UTF-8 で書いた日本語コメント（`REM …`）のバイト列が壊れ、断片が不正なコマンドとして誤実行されていた。エラーで `pause` 到達前にコケる／読めないため、ウィンドウが即閉じに見えていた。`chcp 65001` を入れても、バッチ自身のコメントのデコードには間に合っていなかった。
- 対策: `scripts/webapp/run_server.bat` と `scripts/webapp/run_server.ps1` の**両方を英語コメント・メッセージのみの純ASCII**に作り直した。
  - ユーザーが設定済みのパスワード `$Pass = "hitl"` はそのまま保持（再書き換え不要）。
  - 非ASCIIバイトが消えたことで誤実行が解消 → エラーが出なくなり、最後の `pause` で正常に停止してログを読める（=ウィンドウ即閉じも解消）。
- 検証: Python で両ファイルのバイト列を走査し、**127超のバイトが1つも無い（完全な純ASCII）**ことを確認。`grep -P` でのASCII判定は環境エラーで誤判定したため Python で確定させた。
- 関連ファイル: `scripts/webapp/run_server.bat`（書き直し）, `scripts/webapp/run_server.ps1`（書き直し・PW保持）
- 関連 Knowledge: Knowledge/windows-batch-file-ascii-only.md

## バッチ→トンネルの起動を公開URL経由で end-to-end 検証し、テスト用トンネルを停止【検証完了・後始末済】

- ユーザー指示「終了→起動確認して」を受け、`run_server.bat` → `run_server.ps1` の連鎖を**実機で起動し、Cloudflare 公開URL経由まで通して**動作確認した（純ASCII化後の最終確認）。
- 起動: バッチから別ウィンドウで uvicorn(port 8000) が起動（`Application startup complete`）、設定済みパスワード `hitl` が子プロセスへ継承され、`cloudflared 2025.8.1` のクイックトンネルが公開URL `https://pilot-bookstore-lyrics-workout.trycloudflare.com` を発行（URLは再起動ごとに変動）。
- 検証結果（すべて期待どおり）:
  - ローカル: 認証なし→401 / `annotator:hitl`→200。
  - **公開URL経由**: `/api/config` 認証なし→**401** / `annotator:hitl`→**200**（classes JSON 返却）/ トップページ→**200**。これで「バッチ起動 → 公開 → 認証 → アプリ配信」が外部到達も含め一気通貫で動作することを実証。
- 起動ログの警告を切り分けて「すべて正常」と説明:
  - `decode_head.classifier MISMATCH ... Reinit due to size mismatch (ckpt:[150...] vs model:[3...])` は**設計どおり**（ADE 150クラスのベース SegFormer を3クラス用にヘッド再初期化してから学習済み重みを被せる）。8回出るのは起動時ウォームアップで8モデルを先読みしているため。
  - `ERR ... cert.pem / origin certificate path` はクイックトンネルでは不要な証明書探索メッセージで無害（接続は `Registered tunnel connection` で確立済み）。
- 後始末: テスト用に立てた**公開トンネル(cloudflared)と uvicorn を停止**（医用画像を公開状態で放置しないため。`taskkill` でプロセス終了 → port 8000 が `stopped`・`no cloudflared running` を確認）。
- 補足提案: 現行 `$Pass = "hitl"` は短いため、配布前に推測されにくい長めの値へ変更することを推奨（動作は現状でも可）。
