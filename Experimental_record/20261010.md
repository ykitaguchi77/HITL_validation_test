## 本番開始前の「他人の ID で作業してしまう」リスクの点検と対策案

### 背景
本番 study 開始にあたり、ユーザーから「ID 入力時に他人の ID で作業してしまわないか、その対策は?」と質問。

### 現状コードの確認結果(コード変更なし)
- ID は全員分が並ぶプルダウンから選ぶだけ(`scripts/webapp/static/js/app.js:40` 付近)。Basic 認証のパスワードは全員共通(`scripts/webapp/backend/main.py:81` 付近)で、サーバ側に本人性を確かめる手段がない。
- 初期選択が `test` のため、本番参加者が切り替え忘れると `test_` 扱いで保存される(回収は可能だが本番から外れる)。
- 完了状況はブラウザ localStorage(`_doneSet`)のみ → 他人の ID を選ぶとその人の Session 1 から普通に開始でき、本人が後で同セッションを行ってもサーバは重複を検知しない。
- 影響: 画像セットは全員共通で、違うのは「どの画像にどの条件(モデル)が当たるか」だけ → 他人の割付で作業すると Latin 方格の均衡が崩れ、本人分と重複する。
- `scripts/webapp/config/experiment.json` の annotators は `['kubota','maeda','kaisho','annotator4','annotator5','annotator6']`(4〜6 は仮名のまま)。

### 提示した対策案(効果順)
1. **個人専用 URL(ランダムトークン `/?t=...`)** — サーバがトークンから ID を決定し、本番ではプルダウンを出さない。
2. **完了状況のサーバ側判定** — `outputs/results/` の保存記録から ID×セッションの完了を判定し、完了済みは開始拒否(端末変更・ブラウザ変更時の重複も防止)。
3. **開始前の本人確認画面**(「kubota さんとして Session 3 を開始します」)+ 作業中の上部バーに名前常時表示。
4. **運用**: 初回立ち会い、各自にリンクを個別送付、annotator4–6 を実名/固定匿名コードに確定。

推奨は 1+2(必要なら 3)。変更範囲は `main.py` と `app.js` に限られ、盲検・保存形式には影響しない。
実装後の検証計画(実サーバ + Playwright): ①トークンなし/プルダウンから本番 ID に入れない ②完了済みセッションは再開不可 ③`test` は従来どおり使える。

### 判断・残件
- ユーザーの実装承認待ち(コード変更・サーバ操作なし)。→ 同日承認され実装(次節)。

## ID 取り違え対策の実装(個人トークン URL + サーバ側完了判定)と実サーバ検証

### 背景
前節の対策案に対し、ユーザーが「1 と 2 で進めてください」と承認(本人確認画面 3 は見送り)。

### 実装内容
- **個人トークン URL**(`/?t=<token>`)
  - `scripts/make_annotator_links.py`(新規): 本番アノテータごとにランダムトークンを発行し `scripts/webapp/config/annotator_tokens.json` に保存。再実行してもトークンは不変、`--base-url https://xxxxx.trycloudflare.com` で配布用リンクを一覧出力。
  - `annotator_tokens.json` は `.gitignore` に追加(git 管理外)。
  - `scripts/webapp/backend/config.py`: `TOKENS_JSON` / `load_tokens()` を追加。
  - `scripts/webapp/backend/main.py`: ident(`test` または個人トークン)→アノテータ名を解決する関数を追加し、**全 API(run/session/predict/practice_gt/submit/abort)で検証**。実名・無効トークンは 403、他人名義の session_id への書込・削除も 403。練習アイテムも冒頭で ident を検証。`/api/config` のプルダウン候補は `test` のみ。トークン→名前を返すエンドポイントで画面に本人名を表示。トークン未発行の本番アノテータは起動時に WARNING。
  - 記録の `annotator` 欄はトークンではなく名前で保存。
- **サーバ側完了判定**
  - `scripts/webapp/backend/session.py`: `completed_attempts(annotator, n_images)` を追加。`outputs/results/` の保存記録から ID×セッションの完了・試行回数を判定(**全画像を提出したセッションのみ完了**扱い、途中のものは未完了)。
  - フロントの ✓・試行回数は localStorage ではなくサーバから取得 → PC/ブラウザを変えても進捗が復元され、重複開始も起きない。
- **フロント**(`scripts/webapp/static/index.html`, `static/js/app.js`, `static/css/style.css`)
  - 個人リンクでは「アノテータ: **kubota**」を大きく表示し、本人でなければ閉じるよう案内。無効リンクは「このリンクは無効です」で停止。リンクなしでは `test` のみ選択可+個人コード入力欄(入力すると本人の画面へ遷移)。
- **ドキュメント**: `scripts/webapp/README_deploy.md`(リンク生成・個別送付手順)、`scripts/webapp/annotator_guide.md`(ログイン手順を個人リンク方式に)、`scripts/webapp/run_server.ps1`(リンク生成の案内)を更新。`tasks/todo.md` に項目追加。

### 検証(ポート 8000 はユーザーの稼働中サーバのため触らず、8011 で別起動)
- API チェック(scratchpad の `api_check.py`): **18 項目すべて PASS**(実名/無効コードは 403、他人名義の保存・削除 403、途中セッションは未完了扱い、`annotator` 欄は名前、`test` は従来どおり)。

## 練習で模範解答(正解マスク)が負荷アンケートに覆われる問題の修正(OK ボタンで明示確認)

### 背景
ユーザー報告:「テストでアノテーションを終了した時にマスクが出るが、その時に負荷アンケートが被ってしまう。正解マスクが出るときは OK ボタンを押さないと次に進まないようにできるか?」

### 再現と原因
- 稼働中のポート 8000 は触らず、ポート 8011 で検証サーバを別起動し Playwright(`?t=test`)で練習2を再現。
- 提出 → 模範解答の点線 + Dice は正しく表示される(`.playwright-mcp/practice_confirm.png`)。しかし右上の「確認OK」を押した瞬間に模範解答が消え、即座に Paas 負荷アンケート(`effort-overlay`)が画像を覆う(`.playwright-mcp/practice_effort.png`)。
- 「確認OK」は模範解答(practice_gt)の読み込みを待たずに押せたため、答えを見ないまま次へ進めてしまう構造だった。

### 実装(フロントのみ: `scripts/webapp/static/index.html`、`scripts/webapp/static/js/app.js`、`scripts/webapp/static/css/style.css`)
- 練習セッションで提出すると、画像下に「OK(模範解答を確認した)」ボタン(`gt-ok`)を表示。
  - 模範解答の読み込み完了まで OK は無効。
  - その間は右上の「確認OK」を隠し、先へ進む手段は OK のみ。
- OK を押して初めて負荷アンケート → 次の画像へ。
- 模範解答を見た後に「修正」で直して再提出すると、再び模範解答 + OK が出る。
- 模範解答の取得に失敗した場合はその旨を表示して OK を押せるようにし、練習が止まらないようにした。
- 本番セッションは変更なし(右上「確認OK」の流れのまま、模範解答も出ない)。

### 検証
- 8011 + Playwright: OK 表示中はアンケート非表示・模範解答は残る(`.playwright-mcp/practice_gt_ok.png`)→ OK 押下でアンケート表示 → 次画像へ、を確認。修正→再提出で再度 OK が出ることも確認。
- 本番セッション: OK ボタンは出ず、右上「確認OK」が従来どおり動作。
- 検証中に新たな保存記録は無し。検証サーバは停止。
- `outputs/results/test_p_manual_a3_20261010-173826` は検証前からあったユーザー自身のテスト記録と判断し、残置。

### 反映
- 変更は静的ファイルのみ → サーバ再起動不要、開いているタブを再読み込みすれば反映(no-cache ヘッダ済み)。全変更未コミット。
